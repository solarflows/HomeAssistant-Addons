## 1. 这是什么

把腾讯 CodeBuddy / WorkBuddy 账号（OAuth 设备授权登录）包装为统一的 OpenAI 兼容接口：

- 多账号池：加权选号、熔断/冷却、会话粘性（多轮对话不跳号）
- OpenAI 兼容：`/v1/chat/completions`（流式/非流式）、`/v1/models`
- Web 管理面板：账号运维、用量分析、模型档位、在线配置（热生效）、运行日志、积分任务（签到/活跃/旅行/保活/成长任务）

## 2. 首次使用

1. 启动加载项（首次启动约数秒完成初始化）。
2. 打开面板：`http://<你的HA>:7863/panel/`。
3. 用**网关密钥**登录（`api_key`）：
   - 设置了 `API_KEY` 选项 → 使用该值；
   - 未设置 → 随机生成，日志打印一次，且保存于 `/config/workbuddy2api-panel/api_key.txt`。
4. 面板「添加账号」→ 按提示完成 OAuth 登录（浏览器内）→ 凭证自动落盘、热加载进池。
5. 客户端配置：
   ```
   base_url: http://<你的HA>:7863/v1
   api_key:  <网关密钥>
   ```

## 3. 健康检查与探测

| 端点 | 说明 |
|---|---|
| `/panel/` | 面板页面（加载项健康检查使用） |
| `/status` | 账号状态汇总 + 明细（需网关密钥） |
| `/healthz` | 无鉴权；**有可用账号才返回 200，否则 503**（设计如此，不适合无账号时直接探活） |

## 4. 配置项

| 配置项 | 说明 |
|---|---|
| `API_KEY` | 网关密钥；留空自动生成。**仅首次生成配置时写入**（seed-once），之后请在面板「配置」页修改 |
| `TZ` | 容器时区，决定签到（9/21 点）、活跃（10 点）、保活（22 点）等定时任务的执行时刻 |

> 面板保存配置采用深合并 + 原子替换；涉及进程装配期的字段（如 `listen`）保存后会提示需重启加载项。

## 5. 数据与备份

| 容器路径 | 内容 | 是否随 HA 备份 |
|---|---|---|
| `/config/workbuddy2api-panel/config.json` | 主配置 | ✅ |
| `/config/workbuddy2api-panel/auths/` | 账号凭据（明文 token） | ✅ |
| `/config/workbuddy2api-panel/api_key.txt` | 网关密钥副本 | ✅ |
| `/config/workbuddy2api-panel/config.example.json` | 上游示例配置（参考用） | ✅ |
| `/data/workbuddy2api-panel/data/` | state.json 池状态、请求归档（默认 7 天 / 100MB 上限） | ❌ |

> 恢复备份后账号池自动对齐 `auths/` 目录；`state.json` 丢失只会重置冷却/统计，不影响账号。

## 6. 与上游 Docker 部署的差异

- 打包上游**官方 release 二进制**（`wb2api`），面板功能完整。
- 未包含 CLI 辅助脚本（`login.sh` / `signin.sh` / `credit.sh`）与探测脚本；账号管理请在面板中完成。
- 以 root 运行（HA 加载项默认），`auths/` 文件权限 0600。

## 7. 故障排查

- **面板打不开 / 提示 401** → 用网关密钥登录；忘记密钥可查看 `/config/workbuddy2api-panel/api_key.txt` 或 `config.json` 中的 `api_key`。
- **健康检查显示 unhealthy** → 若尚未添加任何账号，属预期（`/healthz` 无账号返回 503 仅影响直接访问该端点；加载项探活用面板页面）。
- **签到/任务未按时执行** → 检查 `TZ` 是否为期望时区；面板「配置」页中定时任务开关是否开启。
- **OAuth 添加账号失败** → 面板给的是设备授权流程，需在浏览器完成登录；若上游接口变动导致失败，请关注上游仓库更新。
- **加载项更新后配置丢失？** → 不会。`config.json` 与 `auths/` 位于 `/config`（HA 快照覆盖）。
